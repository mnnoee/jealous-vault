# ADR-0003: Без сервера и без долгоживущего демона

[English](../0003-no-daemon.md) · Русский

- Статус: принято
- Дата: 2026-11-20

## Контекст

Backup-агент работает от root и читает системные пути. Долгоживущий демон добавил бы на каждый хост
входящий сокет, парсер запросов, аутентификацию, разделение привилегий и супервизор. Операционная
система уже даёт планировщик, логирование, политику перезапуска и лимиты ресурсов. restic уже даёт
формат репозитория, шифрование и дедупликацию.

## Решение

JealousVault - CLI однократного запуска. Его запускает systemd, OpenRC, cron, runit или `tick`, он
делает работу и завершается. Нет сервера, нет слушающего порта и нет протокола агента. Алерты только
исходящие. Движок хранения - restic, вызываемый как дочерний процесс, поэтому репозиторий остаётся
совместимым с обычным restic.

## Последствия

- Малая поверхность атаки: нет сетевого сервиса, который нужно аутентифицировать и патчить.
- Простая отладка: та же команда работает интерактивно и из таймера.
- Нет центрального обзора флота, push с сервера и удалённого триггера кроме SSH или планировщика.
  Управление флотом - будущий платный продукт в отдельном репозитории.
- Планировщик отвечает за параллелизм, логирование и перезапуск; агент управляет только собственной
  блокировкой и повторами.
- Скомпрометированный root на хосте может прочитать пароль репозитория. Это неотъемлемо для
  локального backup-агента и описано в модели безопасности.

## Рассмотренные альтернативы

- **Демон с HTTP API**: добавляет удалённую поверхность атаки и сервис, который нужно защищать на
  каждом хосте.
- **Центральный сервер, который раздаёт задания**: требует связности, учётных данных и сервера;
  не соответствует цели «один хост, работа без сети».
- **Собственный формат репозитория**: теряет совместимость с restic, зрелость шифрования и ручной
  аварийный выход.
