# ADR-0001: TOML для конфигурации

[English](../0001-toml-config.md) · Русский

- Статус: принято
- Дата: 2026-11-20

## Контекст

Агент настраивается оператором на сервере, часто по SSH, и файл просматривается в diff. Нужны комментарии, вложенные секции, массивы и предсказуемое экранирование. Неверная настройка может молча остановить backup, поэтому неизвестные ключи должны отвергаться, а не игнорироваться. UI и центрального сервиса конфигурации нет.

## Решение

Конфигурация - TOML, парсится через `github.com/BurntSushi/toml`. Файл лежит в `/etc/jealous-vault/config.toml`, по одному файлу на job. Декодирование строгое: любой ключ, не отображённый в поле, - ошибка. Длительности и размеры остаются человекочитаемыми строками в файле и парсятся с валидацией при загрузке.

## Последствия

- Конфиг читаемый, с комментариями и удобный для diff.
- Опечатка падает громко, а не отключает backup молча.
- Добавлять ключи легко; переименование или удаление требует окна deprecation и, в итоге, команды миграции.
- Версии схемы пока нет, поэтому старый бинарник отвергает новый конфиг. Это приемлемо до 1.0, но `config migrate` входит в MVP.

## Рассмотренные альтернативы

- **YAML**: ошибки отступов и неявная типизация слишком легко ломают файл, который управляет backup.
- **JSON**: нет комментариев, шумные diff, оператор не может оставить заметку рядом с путём.
- **Только флаги и переменные окружения**: неуправляемо для десятков настроек, хуков и нескольких job.
- **Центральный сервис конфигурации**: добавляет сервер и сетевую зависимость к локальному инструменту.
